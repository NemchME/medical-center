# 8. Руководство по админке

Доступно после входа под пользователем с ролью `admin` или `manager`.

## Вход

1. Откройте `http://localhost:5173`
2. Перейдите в `/login`
3. Введите `admin@medecina.ru` / `admin12345`
4. После входа автоматически редирект в `/admin/patients`

В сайдбаре слева — 7 пунктов меню для администратора.

## Пациенты — `/admin/patients`

### Просмотр

Таблица со столбцами: ID, ФИО, Дата рождения, Телефон, Email + действия.

Клик по строке → модалка с полной карточкой и историей приёмов (с цветными индикаторами риска неявки).

Поиск — по ФИО, телефону, email.

### Добавить пациента

1. Кнопка **«Добавить пациента»** (правый верхний угол)
2. Заполнить форму:
   - **ФИО** *(обязательно)*
   - Дата рождения
   - Пол (мужской/женский)
   - Телефон
   - Email
   - Адрес
3. **Создать**

Создаётся запись `Patient` без привязки к user (без логина). Если пациенту нужен логин — используйте `POST /auth/register` с `role: "patient"` (это автоматически создаст и user, и patient).

### Редактировать

Иконка карандаша в строке таблицы → форма редактирования. Поля те же.

### Удалить

Иконка корзины. **Hard delete** — запись удаляется навсегда. Если у пациента есть приёмы — Prisma выбросит ошибку из-за foreign key. Сначала удалите/отмените приёмы.

## Записи на приёмы — `/admin/appointments`

### Дашборд

4 виджета сверху: всего, сегодня, подтверждённых, неявок.

Таблица всех приёмов с колонками:
- ID
- Пациент
- Врач + специализация
- Центр
- Дата/Время
- Длительность
- Статус (бейдж)
- **Прогноз** — цветной индикатор риска неявки

### Фильтры

- Статус
- Врач
- Дата от/до
- Кнопка «Сбросить»

Применяются мгновенно через React Query.

### Создать запись

1. Кнопка **«Создать запись»**
2. Форма:
   - **Пациент** *(обязательно)* — select из существующих
   - **Врач** *(обязательно)*
   - **Центр** *(обязательно)*
   - **Дата** + **Время** *(обязательно)*
   - **Длительность** — 15/30/45/60/90 мин
3. **Создать**

При создании запускается полный flow: запись → ML-прогноз → 2 уведомления (24ч и 1ч). Прогноз сразу видно в таблице.

## Врачи — `/admin/doctors`

### Просмотр

Таблица: ФИО, Специализация, Центр, Стаж + действия. Клик по строке → карточка с полным расписанием и историей приёмов.

### Добавить врача

1. **«Добавить врача»** → форма:
   - **ФИО** *(обязательно)*
   - **Центр** *(обязательно)*
   - **Email** *(обязательно)* — для логина в систему
   - **Пароль** — по умолчанию `doctor12345`
   - Специализация
   - Стаж
   - Образование
   - URL фото
   - Описание (bio)
2. **Создать**

При создании автоматически:
- Регистрируется новый user через `/api/auth/register` с `role: "doctor"`
- Создаётся Doctor с привязкой к этому user

После создания врач сразу может зайти в систему под своим email/паролем и попасть в `/doctor/schedule`.

### Расписание

Иконка календаря 📅 → модалка редактора расписания.

Чекбоксы по дням недели + время начала/конца + длительность слота. Если день не отмечен — выходной.

При сохранении бэкенд делает `PUT /api/doctors/:id/schedule` с массивом активных дней — старое расписание полностью заменяется новым.

### Редактировать

Иконка карандаша. Можно менять центр, специализацию, опыт, фото, био. Email/пароль не меняются (это user, не doctor).

### Удалить

Корзина. **Hard delete** — каскадных правил нет, поэтому если у врача есть приёмы — нужно сначала их удалить/отменить.

## Центры — `/admin/centers`

Карточная сетка. Каждая карточка = центр с адресом, телефоном, email.

### Добавить центр

Форма:
- **Код** *(обязательно)* — уникальный, например `MSK-04`
- Часовой пояс — `Europe/Moscow` по умолчанию
- **Название** *(обязательно)*
- Адрес
- Телефон
- Email

### Редактировать

Карандаш. Код менять нельзя (он `unique`).

### Деактивировать

Корзина → soft delete (`isActive: false`). Центр пропадает из публичных запросов, но остаётся в БД (приёмы сохраняют ссылку).

## Услуги и анализы — `/admin/services`

Две вкладки: **Медицинские услуги** и **Анализы**.

### Услуги

Таблица: код, название, длительность, цены по центрам + действия.

#### Добавить услугу

- **Код** *(обязательно)* — уникальный (`CONS-CARD`, `MRI-HEAD`)
- **Название** *(обязательно)*
- Описание
- Длительность по умолчанию (5-240 мин)

#### Установить цену

Иконка $ → модалка «Цены: <название>».
- Выбрать **Центр**
- Указать **Цену в рублях**
- **Установить**

При установке новой цены старая для пары `(serviceId, centerId)` автоматически деактивируется (`isActive: false`, `validTo: now()`). Это сохраняет историю цен.

#### Деактивировать

Корзина → soft delete. Услуга больше не появляется в публичном каталоге, но цены и приёмы с ней остаются.

### Анализы

То же самое, плюс поля:
- **Биоматериал** (Кровь из вены, Моча, …)
- **Подготовка** (Натощак, …)

## Аналитика — `/admin/analytics`

Реальные графики на `recharts` с данными из БД:

| Виджет | Что показывает |
|---|---|
| 4 KPI-карточки | Всего пациентов, всего записей, % неявок, кол-во врачей |
| **Записи по месяцам** | BarChart, последние 12 мес: всего vs неявки |
| **Статусы записей** | PieChart |
| **Загрузка врачей** | Horizontal BarChart, кол-во приёмов за 30 дней |

Данные обновляются через React Query (без window-focus refetch — нужен мануальный refresh).

## Уведомления — `/admin/notifications`

Список всех `notification`-ов с фильтром по статусу: Все / Ожидают / Отправлены / Ошибка.

Колонки:
- ID
- Тип (`reminder_24h`, `reminder_1h`, `confirmation`, `cancellation`)
- Приём (имя пациента + врача)
- Запланировано (дата/время)
- Отправлено
- Статус
- Действия

### Действия

Для уведомлений со статусом `pending`:
- ✅ Зелёная галочка → отметить как отправленное
- ❌ Красный крестик → отметить как failed

Для всех:
- 🗑 Корзина → удалить

## Полезные сценарии

### Создать врача с полным набором

1. `/admin/doctors` → «Добавить врача» → заполнить форму, создать
2. В таблице найти нового врача → 📅 «Расписание» → отметить рабочие дни → сохранить
3. Готово — врач может логиниться, у него есть расписание

### Завести пациенту первый приём с услугами

1. Если пациент новый — `/admin/patients` → «Добавить пациента»
2. `/admin/appointments` → «Создать запись» → выбрать пациента, врача, центр, дату/время, создать
3. *(Пока через UI нельзя добавлять услуги к существующему приёму — используйте API `POST /api/appointments/:id/services` с `serviceId, qty`)*

### Заменить прайс на услугу

1. `/admin/services` → вкладка «Медицинские услуги»
2. Найти услугу → 💲 «Цены»
3. Выбрать центр → ввести новую цену → «Установить»
4. Старая цена становится неактивной, новая вступает в силу для всех новых приёмов

### Просмотреть аналитику клиники

`/admin/analytics` → все графики автоматически считаются по реальным данным из БД через эндпоинты `/api/analytics/*`.

## Известные ограничения

- Нет привязки услуг к существующему приёму через UI (только при создании)
- Нет редактирования цен в виде истории (только установка новой)
- Нет UI для управления типами документов и file storage
- Нет bulk-операций (массовое удаление, импорт CSV)
- Нет редактирования email/пароля врача через админку (только сброс пароля через DB или доработка API)
